# DocFlow 2.0 — Node.js + PostgreSQL

ย้ายจาก Google Apps Script + Google Sheets มาเป็นแอปที่รันได้ทุกที่ด้วย Docker
หน้าเว็บ (`public/index.html`) ใช้ของเดิมเกือบทั้งหมด เปลี่ยนเฉพาะส่วนที่เรียกเซิร์ฟเวอร์จาก `google.script.run` เป็น JSON API

## โครงสร้าง

```
db/schema.sql          โครงสร้างฐานข้อมูล PostgreSQL (ระบบรันให้เองทุกครั้งที่เปิด)
src/server.js          Express server + งานตั้งเวลา (แจ้งเตือน License 08:00, สำรองข้อมูล 02:00)
src/api.js             รายการ API + ตรวจสิทธิ์ (เดิม apiTable_ / api ใน Platfrom.gs)
src/platform.js        ผู้ใช้ ล็อกอิน หลายบริษัท License          (เดิม Platfrom.gs)
src/documents.js       เอกสารขาย ข้อมูลบริษัท สรุปยอด             (เดิม Code.gs)
src/modules.js         สมุดรายชื่อ สินค้า ค่าใช้จ่าย ซื้อ/รับสินค้า   (เดิม Modules.gs)
src/uploads.js         อัพโหลดไฟล์                                (เดิม Upload.gs)
src/print.js           แม่แบบพิมพ์ + PDF (Chromium) + สำรอง PDF
src/reports.js         รวมรายได้ / แดชบอร์ดข้ามบริษัท
src/backup.js          สำรอง/นำเข้าข้อมูลทั้งหมดเป็น JSON
src/storage/           ที่เก็บไฟล์: local.js (โฟลเดอร์ Storage) / layout.js (ชื่อหมวด)
src/i18n/en.json       พจนานุกรมไทย→อังกฤษ (เดิม En.gs)
views/print.ejs        แม่แบบเอกสาร A4 (เดิม Print.html)
public/                หน้าเว็บ + favicon + โลโก้
scripts/               สร้างผู้ดูแล รีเซ็ตรหัสผ่าน ตั้ง Super Admin สำรอง/นำเข้า
```

## ฐานข้อมูล: จาก Google Sheets เป็น PostgreSQL

| เดิม (Google Sheets) | ใหม่ (PostgreSQL) |
|---|---|
| 1 บริษัท = 1 ไฟล์ Google Sheet | ฐานข้อมูลเดียว ทุกตารางมีคอลัมน์ `tenant_id` |
| แท็บ Tenants / Users / Licenses ในชีตหลัก | `tenants`, `users`, `license_keys` |
| Documents / DocumentItems | `documents`, `document_items` |
| CompanyProfiles (+ โลโก้) | `company_profiles` (โลโก้เก็บในคอลัมน์ `logo`) |
| Contacts, Products | `contacts`, `products` |
| Expenses / ExpenseItems / ExpenseCategories | `expenses`, `expense_items`, `expense_categories` |
| PurchaseDocs / PurchaseItems | `purchase_docs`, `purchase_items` |
| Uploads, AuditLog | `uploads`, `audit_log` |
| ค้นหา PDF สำรองจากชื่อไฟล์ | `pdf_backups` |
| Settings / Customers | ไม่ใช้แล้ว (ค่าตั้งระบบอยู่ใน `app_settings`) |
| LockService | `pg_advisory_xact_lock` ต่อบริษัท + ทุกคำขออยู่ใน transaction |
| CacheService | ไม่จำเป็น (อ่านจากฐานข้อมูลโดยตรง) |

รหัสผ่านใช้อัลกอริทึมแฮชเดียวกับระบบเดิม ถ้าย้ายข้อมูลผู้ใช้มา รหัสผ่านเดิมใช้ได้ต่อ

## รันด้วย Docker

```bash
cp .env.example .env          # (ไม่บังคับ) แก้ POSTGRES_PASSWORD และค่าที่เก็บไฟล์
docker compose up -d --build
docker compose logs -f app    # ดูว่าขึ้น "DocFlow listening on :3000"
```

**เข้า Postgres/Adminer ไม่ได้ ("password authentication failed")** — เกิดเมื่อแก้ `POSTGRES_USER`/`POSTGRES_PASSWORD` ใน `.env` หลังจากฐานข้อมูลถูกสร้างไปแล้ว แก้โดยไม่ลบข้อมูล:
`sh scripts/fix-db-login.sh`

ถ้าเคยรันแล้วเปลี่ยน `POSTGRES_PASSWORD` ทีหลัง ฐานข้อมูลเดิมยังใช้รหัสเก่า ให้ลบ volume ก่อน (ข้อมูลหาย): `docker compose down -v`

เปิด `http://<เซิร์ฟเวอร์>:3000` ครั้งแรกระบบจะให้สร้างผู้ดูแลระบบคนแรก (เป็น Super Admin อัตโนมัติ)
หรือสร้างจาก command line: `docker compose exec app node scripts/create-admin.js admin <รหัสผ่าน>`

ขึ้นใช้งานจริงควรวางหลัง reverse proxy ที่มี HTTPS (Nginx, Caddy, Cloudflare Tunnel ฯลฯ)

## ดูข้อมูลในฐานข้อมูล

| วิธี | ใช้อย่างไร |
|---|---|
| psql ในคอนเทนเนอร์ | `docker compose exec db psql -U docflow docflow` |
| หน้าเว็บ Adminer | ปิดไว้เป็นค่าเริ่มต้น เปิดด้วย `docker compose --profile adminer up -d adminer` (ใช้เสร็จสั่ง `docker compose stop adminer`) แล้วเปิด `http://localhost:8080` → System: PostgreSQL, Server: `db`, Username/Database: `docflow`, Password: ค่า `POSTGRES_PASSWORD` |
| โปรแกรม DBeaver / pgAdmin / TablePlus | Host `localhost`, Port `5432`, Database/User `docflow`, Password ค่า `POSTGRES_PASSWORD` |

พอร์ต 5432 และ 8080 เปิดเฉพาะบนเครื่องเซิร์ฟเวอร์ (`127.0.0.1`) ถ้าเซิร์ฟเวอร์อยู่บน cloud ให้เข้าผ่าน SSH tunnel เช่น
`ssh -L 8080:localhost:8080 -L 5432:localhost:5432 user@เซิร์ฟเวอร์` แล้วเปิดบนเครื่องตัวเองตามปกติ

การแก้/ลบข้อมูลตรงในฐานข้อมูลจะไม่ถูกบันทึกในประวัติ (`audit_log`) และไม่คำนวณยอด/สต็อกให้ใหม่ ควรใช้ดูข้อมูลเป็นหลัก

## ที่เก็บไฟล์: โฟลเดอร์ Storage

ไฟล์ทั้งหมดเก็บในระบบ ที่โฟลเดอร์ `Storage` ข้างไฟล์ `docker-compose.yml` (เปิดดูบนเครื่องเซิร์ฟเวอร์ได้ตรง ๆ) ระบบแยกหมวดให้เอง

```
Storage/
├─ 01 เอกสาร PDF   / [บริษัท] / 01 ใบเสนอราคา … 09 สินค้า / (_ยกเลิก) / [ปี] / [MM เดือน] / yyyy-MM-dd_เลขที่_ลูกค้า.pdf
├─ 02 ไฟล์อัพโหลด  / [บริษัท] / 01 สลิปโอนเงิน, 02 ใบเสร็จ-ใบกำกับภาษี, 03 ใบเสร็จค่าใช้จ่าย, 04 สัญญา … 99 อื่นๆ / [ลูกค้า] / [ปี] / [MM เดือน]
├─ 03 สำรองข้อมูล  / [yyyy-MM-dd] / docflow-backup-HHmmss.json.gz   (สำรองอัตโนมัติทุกวัน เก็บ 30 วัน)
└─ 99 ถังขยะ       / ไฟล์ที่ถูกลบจากหน้าเว็บ (คงโครงสร้างเดิมไว้)

### ถังขยะ
- ลบไฟล์อัพโหลด / แทนที่ PDF ฉบับเดิม → ย้ายไป `99 ถังขยะ` และบันทึกในตาราง `trash_items`
- ลบเอกสาร (ใบเสนอราคา / ใบวางบิล / ใบกำกับภาษี-ใบเสร็จ / ขายเงินสด / ค่าใช้จ่าย / ใบสั่งซื้อ / ใบรับสินค้า) → เก็บข้อมูลทั้งชุด
  (ตาราง `trash_items.payload` + สำเนา `99 ถังขยะ/เอกสารที่ลบ/[บริษัท]/[ประเภท]/*.json`) ไฟล์แนบและ PDF ของเอกสารย้ายไปถังขยะในกลุ่มเดียวกัน
- กู้คืนเอกสาร = ข้อมูลเอกสาร + รายการ + ไฟล์แนบ + PDF กลับที่เดิม พร้อมปรับสถานะที่เกี่ยวข้อง (ใบวางบิลชำระแล้ว, สต็อก, ใบสั่งซื้อรับของแล้ว)
- เลขที่เอกสารที่อยู่ในถังขยะจะไม่ถูกใช้ซ้ำ จึงกู้คืนได้ด้วยเลขเดิมเสมอ
- เก็บไว้ `TRASH_KEEP_DAYS` วัน (ค่าเริ่มต้น 30) แล้วลบถาวรอัตโนมัติทุกวัน 03:00 (`TRASH_CRON`)
- เมนู "ถังขยะ": Super Admin เห็นทุกบริษัท · Admin และผู้ตรวจสอบ (Admin Audit) เห็นเฉพาะบริษัทที่มีสิทธิ์ — ค้นหา, กู้คืนกลับที่เดิม, ลบถาวรทันที (พนักงาน/ผู้ดูอย่างเดียว เรียก API นี้ไม่ได้)
```

- เปลี่ยน "ประเภทไฟล์" ของไฟล์อัพโหลดในหน้าเว็บ ระบบจะย้ายไฟล์ไปหมวดใหม่ให้
- ชื่อหมวดแก้ได้ที่ `src/storage/layout.js` (แก้ก่อนเริ่มใช้งาน ไฟล์เดิมจะไม่ถูกย้ายตาม)
- **ควรสำรองโฟลเดอร์ `Storage` ไปเก็บที่อื่นเป็นระยะ** (เช่น rsync / คัดลอกขึ้น cloud) เพราะถ้าเซิร์ฟเวอร์เสีย ไฟล์จะหายไปพร้อมกัน

## JSON API

```
POST /api/public/<fn>   body: {"args": [...]}                 authStatus, login, createFirstAdmin, activateLicense
POST /api/call/<fn>     headers: Authorization: Bearer <token>
                                 X-Tenant-Id: <id บริษัท>
                        body:    {"args": [...]}
ผลลัพธ์: {"result": ...} หรือ {"error": "ข้อความ"} (HTTP 400)
```

ชื่อฟังก์ชันและอาร์กิวเมนต์เหมือนระบบเดิมทุกตัว (ดูรายการใน `src/api.js`) เช่น

```bash
curl -X POST http://localhost:3000/api/call/listDocuments \
  -H "Authorization: Bearer $TOKEN" -H "X-Tenant-Id: $TENANT" \
  -H "Content-Type: application/json" -d '{"args":[""]}'
```

## สำรอง / ย้ายข้อมูล

- ระบบสำรองข้อมูลทั้งหมดเป็น JSON (gzip) ทุกวัน 02:00 ไว้ที่ `Storage/03 สำรองข้อมูล/<วันที่>/` เก็บ 30 วัน
- สำรองเอง: `docker compose exec -u node app node scripts/backup.js /app/Storage/backup.json`
- นำเข้า (แทนที่ข้อมูลทั้งหมด): `docker compose exec -u node app node scripts/restore.js /app/Storage/backup.json --yes`
- สำรองระดับฐานข้อมูล: `docker compose exec db pg_dump -U docflow docflow > docflow.sql`

## คำขอลบบริษัท (ต้องให้ Super Admin อนุมัติ)
- **ส่งคำขอ:** ผู้ดูแลหรือผู้ตรวจสอบกดปุ่ม 🗑 ที่การ์ดบริษัท (หน้า "บริษัทของฉัน") แล้วใส่เหตุผลและพิมพ์ชื่อบริษัทยืนยัน คำขอจะถูกส่งไปให้ Super Admin
- **ระหว่างรออนุมัติ:** ยังใช้บริษัทได้ตามปกติ และกด "ยกเลิกคำขอลบ" ได้
- **ฝั่ง Super Admin:**
  - ได้รับแจ้งเตือนทันที (เสียง + Telegram ถ้าตั้งไว้)
  - ดูคำขอได้ที่ "ติดตามผู้ใช้งาน" → การ์ด **คำขอลบรออนุมัติ** มีรายละเอียดข้อมูลที่จะถูกลบ ช่องหมายเหตุ และปุ่มอนุมัติ / ไม่อนุมัติ
  - กดอนุมัติแล้วระบบจะสำรองข้อมูลทั้งระบบก่อน แล้วจึงลบบริษัท
- **ผลลัพธ์:** ผู้ขอได้รับแจ้งเตือนทันที และเห็นประวัติคำขอทั้งหมดพร้อมสถานะและหมายเหตุที่หน้า "บริษัทของฉัน"

## ดาวน์โหลดข้อมูลทั้งบริษัท (ส่งมอบข้อมูลให้ลูกค้า)
กดปุ่ม ⬇ ที่การ์ดบริษัท (หน้า "บริษัทของฉัน") → "สร้างไฟล์ใหม่" ระบบจะสร้างไฟล์ .zip เบื้องหลัง และแจ้งเตือนเมื่อพร้อม ในไฟล์มี:
- **PDF:** เอกสารทุกใบ (ขาย / ซื้อ / ค่าใช้จ่าย) แยกโฟลเดอร์ตามประเภท
- **ไฟล์อัปโหลด:** ไฟล์แนบทั้งหมดตามโครงสร้างโฟลเดอร์เดิม
- **ตารางข้อมูล:** ไฟล์ .csv เปิดด้วย Excel ได้
- **ข้อมูลบริษัท:** ข้อมูลบริษัท โลโก้ และ `data.json` (ข้อมูลดิบทั้งหมด)

**ระยะเวลาเก็บไฟล์:** ไฟล์เก็บที่ `Backups/exports` ดาวน์โหลดได้ `EXPORT_KEEP_DAYS` วัน (ค่าเริ่มต้น 30) แล้วลบอัตโนมัติ ระบบบันทึกจำนวนครั้งและเวลาที่ดาวน์โหลด

**เมื่อ Super Admin อนุมัติคำขอลบบริษัท:**
1. ระบบสร้างไฟล์ข้อมูลทั้งบริษัทให้ลูกค้าก่อน
2. แล้วจึงลบบริษัท (สำรองข้อมูลทั้งระบบก่อนลบเหมือนเดิม)
3. ลูกค้าดาวน์โหลดไฟล์ได้จาก "คำขอลบบริษัทของคุณ"

ถ้าสร้างไฟล์ไม่สำเร็จ ระบบจะไม่ลบบริษัท และคืนคำขอเป็น "รออนุมัติ" พร้อมเหตุผล ในหน้าคำขอฝั่ง Super Admin จะแสดงด้วยว่าลูกค้าดาวน์โหลดข้อมูลไปแล้วหรือยัง

## ตั้งค่าสมัครใช้งานฟรี (Super Admin)
ที่เมนู "License ผู้ใช้" มีกล่อง "🎁 สมัครใช้งานฟรี (ทดลองใช้)":
- **เปิด/ปิดรับสมัคร:** สวิตช์เปิดปิด · ปิดแล้วปุ่ม "สมัครใช้งานฟรี" จะไม่แสดงที่หน้าเข้าสู่ระบบ
- **กำหนดวันทดลองใช้ฟรีได้เอง:** 1–3650 วัน (มีผลกับผู้ที่สมัครใหม่หลังจากนั้น)
- ค่านี้เก็บในฐานข้อมูล แก้ได้ทันทีโดยไม่ต้องแก้ `.env` หรือรีสตาร์ท · ค่าใน `.env` (`TRIAL_DAYS`, `ALLOW_SIGNUP`) เป็นเพียงค่าเริ่มต้นก่อนตั้งในหน้าเว็บ

## ปรับโควตาบริษัทแบบด่วนที่หน้า "ผู้ใช้งานระบบ"
- ใต้ชื่อเจ้าของบัญชี (ผู้ตรวจสอบ/Admin Audit) มี 2 ชิปให้ Super Admin คลิกปรับได้ทันที:
  - ชิป 👥 = โควตาการสร้างผู้ใช้
  - ชิป 🏢 = โควตาการสร้างบริษัท
- คลิกชิปใดก็เปิดกล่องตั้งค่า (ใช้ค่าเริ่มต้น / กำหนดเอง / ไม่จำกัด) · เห็นและกดได้เฉพาะ Super Admin

## แจ้งคำขอในกล่องข้อความ + ลบข้อความแชท
- เมื่อผู้ใช้กด "ขอเพิ่มบริษัท" หรือ "ขอเพิ่มผู้ใช้" ระบบจะ**โพสต์ข้อความคำขอเข้ากล่องข้อความ**ของผู้ใช้นั้นด้วย Super Admin จึงเห็นคำขอได้ทั้งที่หน้า "ติดตามผู้ใช้งาน" และในเมนู "กล่องข้อความ" (ขึ้นสถานะ "รอตอบ")
- **Super Admin ลบข้อความแชทได้:** ชี้เมาส์ที่ข้อความใด ๆ ในกล่องข้อความจะมีไอคอนถังขยะ กดเพื่อลบถาวร (ลบไฟล์แนบด้วย · ทั้งสองฝ่ายจะไม่เห็นข้อความนั้นอีก)

## โควตาการสร้างบริษัท + คำขอเพิ่มสิทธิ์
- ผู้สมัครใช้งานเอง (เจ้าของบัญชี) สร้างบริษัทได้ตามโควตา · **ค่าเริ่มต้น 1 บริษัท** (ตั้งค่าได้ที่ `SIGNUP_COMPANY_QUOTA` หรือหน้า License)
- หน้า "บริษัทของฉัน" แสดงแถบ "สร้างบริษัทไปแล้ว X / Y บริษัท" · เมื่อครบโควตา ปุ่ม "เพิ่มบริษัท" จะซ่อน และมีปุ่ม **"ขอเพิ่มบริษัท"** แทน
- เช่นเดียวกับผู้ใช้: เมื่อโควตาผู้ใช้เต็ม จะมีปุ่ม **"ขอเพิ่มผู้ใช้"** ที่หน้า "ผู้ใช้งานระบบ"
- คำขอทั้งสองแบบจะไปโผล่ที่หน้า "ติดตามผู้ใช้งาน" ของ Super Admin (การ์ด **"คำขอเพิ่มสิทธิ์"**) พร้อมแจ้งเตือนทันที + Telegram · Super Admin กำหนดจำนวนที่อนุมัติแล้วกด "อนุมัติ" (เพิ่มโควตาให้ทันที) หรือ "ไม่อนุมัติ"
- **Super Admin เพิ่มบริษัทให้ผู้ใช้ได้เอง:** หน้า "ติดตามผู้ใช้งาน" → การ์ด "บริษัทในระบบ" จัดกลุ่มบริษัทตามเจ้าของ (ผู้สมัครคนแรก) · แต่ละกลุ่มมีปุ่ม "＋ เพิ่มบริษัทให้ผู้ใช้นี้"
- กำหนดโควตาบริษัทรายคนได้ในฟอร์มแก้ไขผู้ใช้ (ใช้ค่าเริ่มต้น / กำหนดเอง / ไม่จำกัด)

## การแสดงผู้ใช้แบบลำดับชั้น
- ที่หน้า "ผู้ใช้งานระบบ" พนักงานที่ถูกสร้างขึ้น จะแสดง **เยื้องเข้าไปอยู่ใต้เจ้าของบัญชี (ผู้ตรวจสอบ/Admin Audit) ที่สร้างเขา** พร้อมเครื่องหมาย ↳ และแถบสีด้านซ้าย ทำให้เห็นชัดว่าผู้ใช้แต่ละคนอยู่ในสังกัดใคร
- เจ้าของบัญชีที่สมัครเองจะอยู่ระดับบนสุด · Super Admin เห็นทั้งระบบ

## โควตาการสร้างผู้ใช้
- ผู้ที่สมัครใช้งานเอง (เจ้าของบริษัท) สร้างบัญชีพนักงานได้ตามโควตา · **ค่าเริ่มต้น 1 คน** หากต้องการเพิ่ม ต้องติดต่อ Super Admin
- หน้า "ผู้ใช้งานระบบ" ของเจ้าของบัญชีจะแสดง "สร้างผู้ใช้ไปแล้ว X / Y คน" และปิดปุ่มเพิ่มเมื่อครบโควตา
- **Super Admin กำหนดได้:**
  - **ค่าเริ่มต้นของทุกคนที่สมัครใหม่:** เมนู "License ผู้ใช้" → กล่องสมัครใช้งานฟรี → ช่อง "สร้างผู้ใช้ได้ (เริ่มต้น)"
  - **รายคน (ด่วน):** ที่หน้า "ผู้ใช้งานระบบ" คลิกชิป "👥 X / เริ่มต้น (Y) ✎" ใต้ชื่อเจ้าของบัญชี → เปิดกล่องตั้งโควตาได้ทันที (ใช้ค่าเริ่มต้น / กำหนดเอง / ไม่จำกัด)
  - **รายคน (ในฟอร์ม):** ปุ่ม "แก้ไข" ผู้ใช้ ก็มีช่อง "โควตาการสร้างผู้ใช้" เช่นกัน
- การลบพนักงานออกจะคืนโควตาให้เจ้าของบัญชีสร้างใหม่ได้

## รูปโปรไฟล์ผู้ใช้
- ผู้ใช้เปลี่ยนรูปของตัวเองได้ที่ "บัญชีของฉัน" (ปุ่มมุมขวาบน) · ผู้ดูแลตั้งรูปให้ผู้ใช้อื่นได้ในฟอร์มเพิ่ม/แก้ไขผู้ใช้
- ระบบย่อรูปให้อัตโนมัติเป็นสี่เหลี่ยมจัตุรัส 256px ก่อนบันทึก (เก็บในฐานข้อมูล ขนาดเล็ก)
- ถ้าไม่มีรูป จะแสดงเป็นวงกลมอักษรย่อพร้อมสีประจำชื่อ
- แสดงรูปที่: ปุ่มผู้ใช้มุมขวาบน, รายชื่อผู้ใช้, หน้าติดตามผู้ใช้งาน และกล่องข้อความ

## ชื่อผู้ใช้และอีเมล
- **เข้าสู่ระบบ:** ใช้ชื่อผู้ใช้หรืออีเมลก็ได้ (ไม่สนตัวพิมพ์เล็ก/ใหญ่)
- **อีเมลห้ามซ้ำ:** อีเมลของแต่ละบัญชีต้องไม่ซ้ำกับอีเมลหรือชื่อผู้ใช้ของบัญชีอื่น
- **บังคับอีเมล:** ผู้ดูแลระบบและผู้ตรวจสอบต้องมีอีเมล ส่วนพนักงานและดูอย่างเดียวไม่บังคับ
- **ตั้งชื่อผู้ใช้เป็นอีเมล:** ระบบใส่ช่องอีเมลให้อัตโนมัติ
- **เตือนชื่อสั้นหรือคำทั่วไป:** ถ้าชื่อผู้ใช้สั้นหรือเป็นคำทั่วไป (admin, staff1, sales…) ฟอร์มจะเตือนให้ใช้อีเมล หรือใส่ชื่อบริษัทนำหน้า เช่น `dduck.staff1` เพราะชื่อผู้ใช้ต้องไม่ซ้ำกันทั้งระบบ

## สมัครใช้งานฟรี (ทดลองใช้)
- หน้าเข้าสู่ระบบมีลิงก์ "สมัครใช้งานฟรี" → กรอกอีเมล (ใช้เป็นชื่อผู้ใช้), เบอร์โทร, รหัสผ่าน → กด "ทดลองใช้งานฟรี"
- ได้บัญชีสิทธิ์ผู้ตรวจสอบ (Admin Audit) + บริษัทของตัวเอง 1 บริษัท และเข้าสู่ระบบทันที · ใช้ฟรี `TRIAL_DAYS` วัน (ค่าเริ่มต้น 7)
- หมดอายุแล้วเข้าสู่ระบบ/ใช้งานไม่ได้ ระบบแจ้งให้ติดต่อเจ้าหน้าที่ (ข้อความติดต่อตั้งได้ที่เมนู License ผู้ใช้) · Super Admin ต่ออายุได้ที่เมนู License
- ตั้งค่า: `ALLOW_SIGNUP` (on/off), `TRIAL_DAYS`, `SIGNUP_PER_HOUR` · ถ้าตั้ง SMTP ไว้ Super Admin จะได้อีเมลแจ้งเมื่อมีผู้สมัครใหม่

## แชทติดต่อเจ้าหน้าที่
- ผู้ใช้ทุกคน (ยกเว้น Super Admin) มีปุ่ม 💬 มุมขวาล่าง — พิมพ์ข้อความ / แนบรูปหรือ PDF (ไม่เกิน `CHAT_MAX_MB` = 5 MB) ถึงเจ้าหน้าที่
- Super Admin ตอบที่เมนู "กล่องข้อความ" (ไอคอนแชทบนแถบซ้าย มีตัวเลขข้อความที่ยังไม่อ่าน) · เห็นข้อมูลผู้ใช้ บริษัท เบอร์โทร และวันหมดอายุ · ตั้งสถานะ รอตอบ / ตอบแล้ว / ปิดเรื่อง
- License หมดอายุ: ยังเข้าสู่ระบบได้แต่เห็นเฉพาะหน้า "บัญชีหมดอายุ" ที่แชทกับเจ้าหน้าที่หรือกรอก License Key ได้ (ระบบตรวจสิทธิ์ที่เซิร์ฟเวอร์ — ฟังก์ชันอื่นใช้ไม่ได้)
- แจ้งเตือนทันทีผ่าน Server-Sent Events (`GET /api/chat/stream`) พร้อมเสียง "ติ๊ง-ด่อง" (ปิด/เปิดได้ที่ปุ่ม 🔔), ตัวเลขบนแท็บเบราว์เซอร์ และแจ้งเตือนบนเดสก์ท็อปเมื่ออยู่แท็บอื่น · มีระบบตรวจซ้ำเป็นระยะสำรองไว้ ·
  ถ้าวาง Nginx ไว้หน้าแอป ให้ปิด buffering ของ path นี้ (`proxy_buffering off;`) · ข้อมูลอยู่ในตาราง `chat_threads`, `chat_messages` · ไฟล์แนบอยู่ที่ `Storage/04 ไฟล์แชท/[ผู้ใช้]/[ปี-เดือน]`
- ถ้าตั้ง SMTP ไว้: แจ้งอีเมล Super Admin เมื่อมีข้อความใหม่ และแจ้งผู้ใช้เมื่อเจ้าหน้าที่ตอบ

## ติดตามผู้ใช้งาน (เมนู ภาพรวม → ติดตามผู้ใช้งาน)
สำหรับ Super Admin, Admin และผู้ตรวจสอบ โดย Super Admin เห็นทุกคน ส่วน Admin และผู้ตรวจสอบเห็นเฉพาะผู้ใช้ที่ตนสร้าง
- ใครออนไลน์อยู่: เปิดหน้าเว็บค้างไว้ หรือมีการใช้งานภายใน 2 นาทีล่าสุด
- กราฟผู้ใช้งานรายวัน 14 วัน, ล็อกอินสำเร็จและไม่สำเร็จ, กิจกรรมรายชั่วโมงของวันนี้ และสัดส่วนสถานะ
- ตารางผู้ใช้: ใช้งานล่าสุด, จำนวนล็อกอินและกิจกรรมใน 7 วัน, อุปกรณ์, IP และ License
- ประวัติการเข้าสู่ระบบ 30 รายการล่าสุด (เก็บในตาราง `login_events`)
- หน้านี้อัปเดตอัตโนมัติทุก 15 วินาที

## ประกาศถึงผู้ใช้ทุกคน (Super Admin)
เมนู กล่องข้อความ → ปุ่ม "สร้างประกาศ"
- เลือกประเภทได้ 3 แบบ: ข่าวสาร, แจ้งปิดปรับปรุง, สำคัญ/เร่งด่วน
- พิมพ์ข้อความ แล้วกำหนดช่วงเวลาที่แสดง (เริ่มแสดง / แสดงถึง) เมื่อหมดเวลาประกาศจะหายไปเอง
- ผู้ใช้ที่เปิดหน้าเว็บอยู่จะได้รับทันที พร้อมเสียงแจ้งเตือน ส่วนคนที่ยังไม่เปิดจะเห็นตอนเข้าระบบครั้งถัดไป
- แสดงเป็นแถบประกาศด้านบน และเลือกให้เด้งหน้าต่างให้กด "รับทราบ" ได้
- ดูได้ว่ามีผู้ใช้รับทราบแล้วกี่คน และหยุดแสดงหรือลบประกาศได้

## เก็บไฟล์บนดิสก์ลูกที่ 2 หรือ NAS (QNAP / Synology / แชร์โฟลเดอร์)
ตั้งใน `.env` ได้ 2 ตำแหน่ง แล้วรัน `docker compose up -d`
- `STORAGE_LOCAL_DIR`: ไฟล์ของระบบ (PDF, ไฟล์อัปโหลด, ไฟล์แชท, ถังขยะ)
- `BACKUP_LOCAL_DIR`: ไฟล์สำรอง (`full/` จากหน้าเว็บ, `daily/` จาก service backup)

**ฐานข้อมูล PostgreSQL ให้อยู่บนดิสก์ในเครื่องเสมอ** ถ้าวางบน NAS แล้วเครือข่ายสะดุด ฐานข้อมูลเสียหายได้

แบบที่แนะนำ: เก็บ Storage บนดิสก์ในเครื่อง (เร็ว) และเก็บ Backups บน NAS (ได้สำเนาอยู่นอกเครื่อง)

**ดิสก์ลูกที่ 2**
```bash
lsblk -f                                   # หาดิสก์ เช่น /dev/sdb1
sudo mkfs.ext4 /dev/sdb1                   # เฉพาะดิสก์ใหม่ (ข้อมูลในดิสก์จะถูกลบ!)
sudo mkdir -p /mnt/data && sudo blkid /dev/sdb1   # จด UUID
echo 'UUID=<UUID> /mnt/data ext4 defaults,nofail 0 2' | sudo tee -a /etc/fstab
sudo mount -a && sudo mkdir -p /mnt/data/docflow/Storage /mnt/data/docflow/Backups
```

**QNAP ผ่าน NFS** (แนะนำสำหรับ Linux)
1. ฝั่ง QNAP:
   - Control Panel → Network & File Services → NFS Service → เปิด NFS
   - Shared Folders → เลือกโฟลเดอร์ (เช่น DocFlow) → Edit Shared Folder Permission → NFS host access
   - ใส่ IP เครื่องเซิร์ฟเวอร์ สิทธิ์ read/write และ Squash = NO_ROOT_SQUASH
2. ฝั่งเซิร์ฟเวอร์:
```bash
sudo apt install -y nfs-common && sudo mkdir -p /mnt/qnap
echo '192.168.1.50:/DocFlow /mnt/qnap nfs defaults,_netdev,nofail,x-systemd.automount 0 0' | sudo tee -a /etc/fstab
sudo systemctl daemon-reload && sudo mount -a && df -h /mnt/qnap
```

**QNAP / Windows share ผ่าน SMB (CIFS)**
```bash
sudo apt install -y cifs-utils && sudo mkdir -p /mnt/qnap
sudo sh -c 'printf "username=docflow\npassword=รหัสผ่าน\n" > /root/.qnap-cred && chmod 600 /root/.qnap-cred'
echo '//192.168.1.50/DocFlow /mnt/qnap cifs credentials=/root/.qnap-cred,uid=1000,gid=1000,file_mode=0660,dir_mode=0770,iocharset=utf8,_netdev,nofail,x-systemd.automount 0 0' | sudo tee -a /etc/fstab
sudo systemctl daemon-reload && sudo mount -a && df -h /mnt/qnap
```
`uid=1000` คือผู้ใช้ที่รันแอปใน container ส่วน `iocharset=utf8` ทำให้ชื่อไฟล์ภาษาไทยถูกต้อง

**ย้ายไฟล์เดิมไปที่ใหม่**
```bash
docker compose stop app
sudo rsync -a Storage/ /mnt/qnap/docflow/Storage/
# แก้ .env: STORAGE_LOCAL_DIR=/mnt/qnap/docflow/Storage
docker compose up -d
```

**ระบบป้องกันเมื่อ NAS หรือดิสก์หลุด**
- ระบบตรวจโฟลเดอร์เก็บไฟล์ทุก 1 นาที โดยดูไฟล์ยืนยัน `.docflow-storage` และสุ่มตรวจไฟล์ที่ฐานข้อมูลอ้างถึง
- ถ้าพบว่ายังไม่ได้ mount ระบบจะ:
  - หยุดบันทึกไฟล์ใหม่และหยุดสำรองข้อมูล เพื่อกันไฟล์ไปอยู่บนดิสก์ผิดลูก
  - แสดงคำเตือนสีแดงในหน้าสำรอง / กู้คืนข้อมูล
  - ให้ `/healthz` ตอบ 503
- พอเชื่อมต่อกลับมา ระบบกลับมาทำงานเอง

## สำรอง / กู้คืนข้อมูลจากหน้าเว็บ (Super Admin)
เมนู ระบบ → **สำรอง / กู้คืนข้อมูล** และมีการ์ดสถานะบนหน้าภาพรวมด้วย
- **สำรองข้อมูลตอนนี้:**
  - รวมฐานข้อมูลทุกบริษัทกับไฟล์ทั้งหมดใน Storage เป็นไฟล์เดียว เช่น `Backups/full/docflow-2026-10-22_193000-manual.tar`
  - ในไฟล์มี `manifest.json` (รายละเอียดและ checksum), `database.json.gz` และ `storage.tar.gz`
- **ตั้งเวลาสำรองอัตโนมัติ:** กดที่แถบ 🕐 ในหน้านี้ เลือกได้ว่า ปิด / ทุกวัน / ทุกสัปดาห์ (เลือกได้หลายวัน) / ทุกเดือน (เลือกวันที่ได้หลายวัน หรือ "วันสุดท้ายของเดือน") พร้อมกำหนดเวลาและจำนวนชุดที่เก็บไว้
  - ค่าที่ตั้งเก็บใน `Backups/full/schedule.json` จึงไม่หายเมื่อกู้คืนข้อมูล
  - ถ้ายังไม่ได้ตั้ง จะใช้ค่าเริ่มต้นจาก `FULL_BACKUP_CRON` / `FULL_BACKUP_KEEP` (ทุกคืน 01:00 เก็บ 7 ชุด)
  - ชุดที่กดสำรองเองไม่ถูกลบอัตโนมัติ
- **ค้นหา:** กรองตามปี / เดือน / วัน / ประเภท
- **ดาวน์โหลด:** ผ่านลิงก์ที่ใช้ได้ครั้งเดียว
- **แฟลชไดรฟ์:** คัดลอกไฟล์ `.tar` จากโฟลเดอร์ `Backups/full` บนเครื่องเซิร์ฟเวอร์ได้โดยตรง
- **กู้คืน:** ต้องพิมพ์ "กู้คืน" เพื่อยืนยัน แล้วระบบทำต่อดังนี้
  1. ตรวจ checksum ของไฟล์
  2. สำรองข้อมูลปัจจุบันไว้ก่อน (ประเภท "สำรองก่อนกู้คืน")
  3. ปิดระบบชั่วคราว ผู้ใช้คนอื่นจะเห็นหน้าจอ "ระบบกำลังกู้คืนข้อมูล"
  4. นำเข้าฐานข้อมูลใน transaction เดียว ถ้าพังกลางทาง ข้อมูลเดิมไม่เปลี่ยน
  5. สลับโฟลเดอร์ Storage แล้วเปิดระบบ ผู้ใช้ทุกคนต้องเข้าสู่ระบบใหม่
- **Log และประวัติ:** ทุกขั้นตอนแสดงเป็น log สด และเก็บประวัติไว้ที่ `Backups/full/history.jsonl` (ไม่หายแม้กู้คืนข้อมูล)
- **กู้คืนจากแฟลชไดรฟ์:** คัดลอกไฟล์ `.tar` กลับไปไว้ใน `Backups/full` แล้วกดกู้คืนในหน้าเว็บ
- **ย้ายไปเครื่องใหม่:**
  1. ติดตั้งระบบใหม่ และสร้างผู้ดูแลคนแรก
  2. วางไฟล์ `.tar` ใน `Backups/full`
  3. กดกู้คืน ข้อมูลผู้ใช้ทั้งหมดจะกลับมาตามชุดสำรอง

## รองรับผู้ใช้พร้อมกัน (ผลทดสอบโหลด)
ทดสอบบนเครื่อง 2 CPU / 8 GB โดยจำลองผู้ใช้ทำงานเอกสารต่อเนื่อง (ดูรายการ เปิดเอกสาร พรีวิว บันทึก สร้าง PDF) ทุก ~3 วินาทีต่อคน ซึ่งถี่กว่าการใช้งานจริงมาก ในบริษัทที่มีเอกสาร 11,000 ใบ

| ผู้ใช้พร้อมกัน | คำขอ/วินาที | ตอบกลับ (ครึ่งหนึ่งเร็วกว่า) | 95% เร็วกว่า | ผิดพลาด |
|---|---|---|---|---|
| 50 | 15 | 0.02 วินาที | 0.5 วินาที | 0 |
| 100 | 28 | 0.04 วินาที | 1.9 วินาที | 0 |
| 200 | 32 | 0.19 วินาที | 7.5 วินาที (คิวสร้าง PDF) | 0 |

- **ขีดสูงสุด:** งานทั่วไป (ไม่รวม PDF) ประมาณ 80 คำขอ/วินาที โดยแอปใช้ CPU 1 core
- **สร้าง PDF:** ทำพร้อมกันได้ `PDF_CONCURRENCY` ไฟล์ (ค่าเริ่มต้น 2) ที่เกินจะต่อคิว
  - คนกดพร้อมกัน 30 คน เสร็จครบใน 7 วินาที ไม่มีผิดพลาด
  - ระหว่างคิว PDF เต็ม งานอื่นยังตอบภายใน 4 ms
- **เลขที่เอกสาร:** บันทึกพร้อมกันหลายพันครั้ง ไม่มีเลขซ้ำ

**คำแนะนำสเปกเครื่อง:** ผู้ใช้ไม่เกิน ~50 คน ใช้ 2 vCPU / 4 GB ได้สบาย ส่วน 100–200 คน แนะนำ 4 vCPU / 8 GB และตั้ง `PDF_CONCURRENCY=3` ถึง `4`

## ความปลอดภัยและความทนทาน
- **IP ผู้ใช้:** เชื่อ IP จาก header (`cf-connecting-ip`, `X-Forwarded-For`) เฉพาะคำขอที่มาจากเครือข่ายภายใน เช่น cloudflared ใน Docker คำขอจากอินเทอร์เน็ตตรง ๆ จึงปลอม IP ไม่ได้
  - ถ้าใช้ผ่าน Cloudflare Tunnel อย่างเดียว ให้ตั้ง `APP_BIND=127.0.0.1` ใน `.env`
- **ใส่รหัสผิด:** ล็อก 10 นาทีเมื่อผิดครบ 5 ครั้ง นับต่อ (IP + ชื่อผู้ใช้) และ 1 IP ผิดรวมได้ไม่เกิน `LOGIN_IP_MAX_FAIL` ครั้ง (ค่าเริ่มต้น 50) คนอื่นจึงล็อกบัญชีเราจากเครื่องของเขาไม่ได้
  - สำนักงานที่ทุกคนออกเน็ตผ่าน IP เดียวกัน ถ้าพนักงานเยอะ ให้ตั้งค่านี้สูงขึ้น
- **รหัสผ่าน:** เก็บแบบ scrypt แฮชรุ่นเก่าถูกอัปเกรดให้อัตโนมัติตอนผู้ใช้ล็อกอินครั้งถัดไป
- **ฐานข้อมูล:**
  - คำสั่ง SQL ใช้เวลาได้ไม่เกิน `PG_STATEMENT_TIMEOUT`
  - transaction ที่ค้างเกิน `PG_IDLE_TX_TIMEOUT` ถูกตัดและปลดล็อกให้เอง
  - ถ้าฐานข้อมูลหลุดชั่วคราว แอปไม่ล่ม
- **PDF:** สร้างหลังปิด transaction แล้ว (ไม่ถือการเชื่อมต่อฐานข้อมูลไว้) และสร้างพร้อมกันได้ไม่เกิน `PDF_CONCURRENCY` ไฟล์ ที่เกินจะต่อคิว
- **ไฟล์สำรอง:** อ่านทุกตารางจาก snapshot เดียวกัน ข้อมูลจึงสอดคล้องกันแม้มีคนบันทึกระหว่างสำรอง
- **Content-Security-Policy:** หน้าเว็บส่งข้อมูลได้เฉพาะเซิร์ฟเวอร์นี้
- **ข้อผิดพลาดทางเทคนิค:** ผู้ใช้เห็นเฉพาะ "รหัสอ้างอิง" ส่วนรายละเอียดอยู่ใน `docker compose logs app` (ค้นหา `ERR <รหัส>`)
- **งานประจำคืน 03:30:**
  - ลบประวัติการเข้าสู่ระบบที่เก่ากว่า `LOGIN_LOG_DAYS` วัน
  - เตือนใน log เมื่อดิสก์ว่างน้อยกว่า `DISK_WARN_PCT` %
  - ดูพื้นที่ดิสก์ได้ที่ `/healthz` และที่การ์ด "พื้นที่ดิสก์ว่าง" ในหน้าติดตามผู้ใช้งาน (เฉพาะ Super Admin)
- **รหัสผ่านฐานข้อมูล:** ต้องตั้ง `POSTGRES_PASSWORD` ใน `.env` ถ้าไม่ตั้ง ระบบจะไม่ยอมเริ่ม (ไม่ใช้รหัสค่าเริ่มต้นแล้ว)
- **ทดสอบกู้คืน:** ควรลองกู้คืนบนเครื่องทดสอบด้วย `scripts/restore-all.sh` เดือนละครั้ง

## แจ้งเตือนและตอบแชทผ่าน Telegram
- **แจ้งเตือน:** ผู้ใช้ส่งข้อความหรือรูป/PDF ในแชท → Bot ส่งเข้า Telegram ของ Super Admin ทันที
- **ตอบกลับ:**
  - กด **Reply** ที่ข้อความนั้นใน Telegram แล้วพิมพ์คำตอบ (ส่งรูปหรือ PDF ได้) คำตอบจะเข้าแชทของผู้ใช้ในระบบทันที
  - ตอบด้วย `/close` เพื่อปิดเรื่อง
- **คำสั่งอื่น:** `/list` ดูห้องที่รอตอบ · `/id` ดู chat ID · `/help`
- **ตั้งค่า:**
  1. สร้าง Bot กับ **@BotFather** (`/newbot`) แล้วใส่ `TELEGRAM_BOT_TOKEN` ใน `.env` จากนั้นรัน `docker compose up -d`
  2. เปิด Bot ใน Telegram แล้วพิมพ์ `/start` Bot จะตอบ chat ID กลับมา
  3. ใส่ค่านั้นใน `TELEGRAM_CHAT_IDS` แล้วรัน `docker compose up -d` อีกครั้ง
- **หลายคนช่วยกันตอบ:** สร้างกลุ่ม Telegram เชิญ Bot เข้ากลุ่ม พิมพ์ `/start` ในกลุ่ม แล้วใช้ chat ID ของกลุ่ม (ขึ้นต้นด้วย `-`) ใส่หลายค่าได้ คั่นด้วย `,`
- **ความปลอดภัย:** Bot รับคำสั่งเฉพาะจาก chat ID ที่กำหนดเท่านั้น
- **ผู้ตอบ:** คำตอบจาก Telegram แสดงในนามของ Super Admin คนแรก หรือคนที่ตั้งไว้ใน `TELEGRAM_REPLY_AS`
- **ดูสถานะการเชื่อมต่อ:** ที่หน้า "กล่องข้อความ"
- **ข้อจำกัด:** 1 Bot Token ใช้ได้ทีละเครื่อง ถ้าเปิดระบบทดสอบด้วย token เดียวกัน จะเกิดการแย่งกันรับข้อความ

## ไม่ใช้ Google Drive / Google Sheet แล้ว
- ข้อมูลทั้งหมดอยู่ใน PostgreSQL และไฟล์ทั้งหมดอยู่ในโฟลเดอร์ `Storage` ของเซิร์ฟเวอร์ (ไม่มีการเชื่อมต่อ Google)
- ไม่มีปุ่ม "สำรองลง Drive" แล้ว — ใช้ "ดาวน์โหลด PDF" หรือ "พิมพ์" แทน · ข้อมูลสำรองอัตโนมัติทุกวันที่ `Storage/03 สำรองข้อมูล`

## เปิดใช้งานผ่านอินเทอร์เน็ตด้วย Cloudflare Tunnel
1. เพิ่มโดเมนไว้ใน Cloudflare (Nameserver ชี้มาที่ Cloudflare แล้ว)
2. Cloudflare Dashboard → **Zero Trust → Networks → Tunnels → Create a tunnel** → เลือก **Cloudflared** → ตั้งชื่อ → คัดลอก token
3. ใน `.env`: `CLOUDFLARE_TUNNEL_TOKEN=<token>` และ `COMPOSE_PROFILES=tunnel` → `docker compose up -d`
4. กลับไปที่ tunnel → แท็บ **Public Hostname → Add**: Subdomain เช่น `docflow`, Domain = โดเมนของคุณ, Service **HTTP** `app:3000`
5. เปิด `https://docflow.โดเมนของคุณ` (HTTPS ให้อัตโนมัติ)
- ไม่ต้องเปิดพอร์ตเราเตอร์ · Adminer/ฐานข้อมูลยังเข้าได้เฉพาะเครื่องเซิร์ฟเวอร์ (อย่าเพิ่ม hostname ให้ Adminer)
- ปิด tunnel: ลบค่า `COMPOSE_PROFILES` แล้ว `docker compose up -d --remove-orphans`
- ตรวจสถานะ: `docker compose logs -f cloudflared` (ต้องเห็น `Registered tunnel connection`)

## สำรองข้อมูลทั้งระบบขึ้น Google Drive
บริการ `backup` (เปิดด้วย `COMPOSE_PROFILES=backup`) สำรองทุกวัน 02:30:
- `daily/docflow-YYYY-MM-DD_HHMM.tar.gz` = ฐานข้อมูล (pg_dump) + `.env` + `docker-compose.yml` · เก็บ 30 วัน + ชุดวันที่ 1 ของเดือน 12 เดือน
- `Storage/` = คัดลอกไฟล์ใหม่/ที่เปลี่ยนจากโฟลเดอร์ Storage (ไม่ลบไฟล์ปลายทาง)
- ปลายทาง: โฟลเดอร์ `BACKUP_LOCAL_DIR` (ค่าเริ่มต้น `./Backups`) และ `RCLONE_REMOTE` (เช่น `gdrive:DocFlow-Backup`)
- สั่งสำรองทันที: `docker compose exec backup sh /backup/backup.sh` · ดูผล: `docker compose logs backup`
- กู้คืนทั้งระบบ: `sh scripts/restore-all.sh <ไฟล์ docflow-....tar.gz> <โฟลเดอร์ Storage ที่สำรองไว้>`

## แก้ปัญหา: ดาวน์โหลด/พิมพ์ PDF ไม่สำเร็จ
- ระบบสร้าง PDF ด้วย Chromium (ในคอนเทนเนอร์) หากขึ้น "สร้าง PDF ไม่สำเร็จ ... (รหัสอ้างอิง XXXXXX)" ให้ดูสาเหตุจริงที่ log:
  ```bash
  docker compose logs app | grep -E "PDF|XXXXXX"   # แทน XXXXXX ด้วยรหัสอ้างอิงที่ขึ้น
  ```
- ตั้งแต่เวอร์ชันนี้ ระบบจะ **เปิด Chromium ใหม่แล้วลองซ้ำอัตโนมัติ 1 ครั้ง** เมื่อ Chromium ค้าง/หลุดการเชื่อมต่อ (สาเหตุที่พบบ่อยหลังเซิร์ฟเวอร์ไม่ได้สร้าง PDF นาน ๆ)
- ถ้ายังไม่หาย ตรวจ: หน่วยความจำว่างพอไหม · `shm_size: "512mb"` ใน docker-compose ยังอยู่ไหม · ลด `PDF_CONCURRENCY` เหลือ 1 · รีสตาร์ต `docker compose restart app`
